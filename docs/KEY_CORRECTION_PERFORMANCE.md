# 按键纠错与提前上屏的缓存复用修复

## 修复范围

修复以 b499329 为基础，保留已经应用的孤立惩罚缓存批量淘汰补丁。
默认 A 档、compact、模型、纠错惩罚、Beam 宽度、双误触搜索范围均未改变。

1. 搜索身份不再包含仅用于末端筛选的 required 文本前缀。相同编码下的前缀变化只筛选、重排缓存终点，不重复搜索。
2. 终点评分按路径缓存，同一码串的不同前缀视图共用原有 EOS 配额。缓存只保存当前搜索代和最后一个筛选视图。
3. 记录第一次评分拒绝所在的源位置。下一代只保留该位置及以前已经完整计算的状态，并重算跨越边界的所有边。被截断的状态从不复用。
4. 选重符涉及的未完成搜索保持保守重建；真实锁定边界、模型代和学习/选项重置仍会使搜索失效。
5. 未完成标记不被缓存命中掩盖；提前上屏安全检查未放宽。配额仍是评分工作量配额，不是墙钟时间上限。

## 回归验证

新增 tools/test_key_correction_reuse.lua，并接入 tools/run_regressions.py。
真实模型：1010项新增检查，309次已完成搜索与同 Beam、无限评分配额的独立全文重算一致，168次受中断前缀续算，5次从中断恢复为完整搜索。
合成模型：899项新增检查。通用回归与23项负对照通过，其中两项专门检出重新引入 required 缓存键、错误复用不完整前缀。
既有真实模型预算测试2369项、纠错正确性测试3378项通过。

## 行为与限制

提前上屏至应用时，完整按键快照并非逐项相同：部分提前上屏时机提前，少数中间候选也改变。15条开发轨迹的最终完整文本中，原有10条正确项全部保持，另恢复1条；不能将此小样本当作正式准确率评测。
下列各组1314个按键快照在修复前后完全一致：纠错关闭且提前上屏开启；纠错开启且提前上屏关闭；纠错开启且提前上屏至编码。
提前上屏至编码会真实改变锁定边界，仍须重新搜索；这一模式没有测得可靠加速，不把它计入优化收益。
没有手机真机测试，也未把修复部署到手机。手机需要同时更新 lua/tiger_sentence.lua 和 lua/tiger_sentence_correction.lua；不需要更换模型。
