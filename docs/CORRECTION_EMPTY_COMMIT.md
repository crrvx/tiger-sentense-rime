# 开启邻键纠错时禁用空码顶屏

## 规则

开启 `tiger_sentence_key_correction` 时，不执行空码顶屏，也不准备该路径的前置候选。
不以当前是否已有纠错候选、码长、模型是否正常加载、剩余编码数量为条件。
禁用分支会清空过期 `empty_code_pending`，但保留概率提前上屏的追踪信息。
关闭纠错时，空码顶屏继续遵守原来的提前上屏开关、最短保留码及竞争切分规则。
“提前上屏至应用”和“提前上屏至编码”两种模式均遵守这条规则；后者也不能提前锁定误码。
概率型提前上屏、手动空格/标点确认、Tab锁定等保持各自路径，不被一起关闭。

## 实现

`try_empty_code_commit()` 在入口检查 `correction.enabled` 并立即清空空码待提交状态后返回。
删除只为纠错模式空码顶屏服务的 `correction.before_append()` 和调用处，以及已经不可能进入的分支。
仍同步处理按键。没有新增线程、异步、开关或缩小搜索；前一轮按需计算上屏证据的优化保留。

## 真实 Rime 验证

纠错开：`pt` 候选为“跃”；继续到 `ptu` 不提交也不锁定“跃”，保留原始 `ptu`。
继续到 `ptue` 首选“是的”，纠正编码 `otue`；手动空格确认提交“是的”。
纠错关：`ptu` 仍按原规则提交“跃”、保留 `u`。
使用真实 librime 及 D89 模型资源验证空格、标点、Tab、退格重输、句中插入、输入中途切换纠错，以及两种上屏目的地，共32项宿主断言通过。

## 回归结果

新增测试已接入 `tools/run_regressions.py`：无模型161项、带真实模型190项；既有证据优化62项、纠错预算2369项、纠错正确性3378项、复用1010项通过。
通用回归及27项负对照通过，新增负对照覆盖绕过禁用条件、保留过期空码待提交状态。
59条轨迹、2轮真实宿主输入，每组2606个按键快照。纠错关闭组、提前上屏关闭组分别全部与修改前一致。
纠错及提前上屏均开启时，提交时机有意改变：应用组348帧、编码区组302帧变化，不声称启用组逐帧等价。
概率提前上屏代码保持不变；真实应用组仍有自动提交。未以这次测试宣称所有长句纠错或提前上屏绝对安全。
